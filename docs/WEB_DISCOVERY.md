# Webアニメ探索エンジン

## 目的

外部検索APIやGeminiを使わず、公開Webページを機械的に巡回し、Web上の「アニメ作品への言及」から未知の作品候補を発見する。
作品専用ホームページの有無は条件にしない。ニュース、ブログ、ポータル、出版社、放送局、制作会社、配信、動画ページ等も同じ探索対象として扱う。

この段階は作品候補の発見を担当する。共通70列CSVへ確定する前には、後段で複数ページの証拠照合と既存重複判定を行う。

## 実行構造

```text
公開Webの起点URL
  ↓
robots.txt確認
  ↓
HTML / XML / RSS / Atom取得
  ↓
本文・title・OGP・JSON-LD・リンクを実行時解析
  ↓
アニメ言及スコアリング
  ↓
作品名候補抽出
  ↓
関連リンクを優先度付きfrontierへ追加
  ↓
別サイトを含めて探索範囲を自己拡張
  ↓
最小限の探索索引と作品候補だけGitHubへ保存
```

## 保存しないもの

HTML全文、記事本文、画像、動画、検索結果スニペットの複製は探索状態へ保存しない。ページ本文はその実行中の判定にだけ使用する。

`crawler/state.json` に保存するのは、URL、ページタイトル、関連度、発見済み作品候補、最終確認日時、未巡回frontier、巡回済みURLのSHA-256だけとする。

## robots.txt / 負荷制御

- `robots.txt` を取得し、Disallow/Allowを判定する。
- robots取得が通信エラー等で確認不能の場合、そのホストは安全側に停止する。
- Crawl-delayがあれば尊重する。
- 独自の最小アクセス間隔を持つ。
- 1ページの最大取得量、1回の最大ページ数、1ホストあたりの上限、最大リンク深度を持つ。
- localhost、プライベートIP、リンクローカル、メタデータ系アドレスへは接続しない。
- 画像・動画・実行ファイル・アーカイブ等は巡回対象外とする。

robots.txtの許可は利用規約や権利上の利用許諾を意味しない。後段で実データを採用・再配布する際の情報源評価は別途必要。

## 作品発見

公式サイトだけを高優先にする設計ではない。ページタイトル、OGP、本文等から次のような言及を検出する。

- `TVアニメ『作品名』`
- `『作品名』アニメ化決定`
- `劇場アニメ「作品名」`
- `新作アニメ 作品名`

発見した作品名は正規化キーでまとめ、どのURLから発見されたかを保持する。同一作品について別サイトから言及が見つかればsource URLが増える。

## 探索優先度

アニメ、作品、キャスト、スタッフ、放送、配信、原作、PV等に関連するリンクを優先する。採用、会社概要、問い合わせ、ログイン、カート等は低優先度とする。

関連度の低いページからは有望なリンクだけを辿る。関連度の高いページからは外部ドメインも含めて一定数まで探索し、特定サイトだけに閉じない。

## 起点URL

検索APIを使わないWebクローラーなので、最初のリンクグラフへ入る起点URLは最低1件必要。`crawler/seeds.txt` またはActionsの `seed_urls` 入力から与える。

これは「作品ごとの情報源指定」ではなく、探索エンジンがWebへ入るための初期ノードである。以後はページ内リンク、JSON-LD URL、sitemap等から探索範囲を増やす。

## GitHub Actions

`Web Anime Discovery` を `workflow_dispatch` で起動する。Cronは持たない。初期値 `dry_run=true`。

- `max_pages`: 1回の最大取得ページ数
- `max_depth`: 起点からの最大リンク深度
- `per_host_limit`: 1回・1ホストあたりの最大取得数
- `seed_urls`: 必要な場合だけ追加する起点

非dry-run時は `crawler/state.json` だけをCommitする。別ファイルが意図せず変更された場合はCommitを拒否し、force pushは使わない。

## 現段階で接続していないもの

- Google / Yahoo / Brave / SerpAPI等の検索API
- Gemini API
- 外部AI検索

探索エンジン自体が公開Webを巡回して候補を発見する。
